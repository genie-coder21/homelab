# History

**2026-10-13: first setup.** Ansible installed from the distro packages on the server. Inventory written for the server (local connection, sudo) and the gaming PC (OpenSSH with the existing admin key, cmd shell type, no Python). Four playbooks: ping, facts, Linux safe-upgrade with a reboot-pending report, and a read-only Windows status playbook that lists the services the server depends on (sshd, SMB for the backup target, Hyper-V for the kids' VMs) and searches for pending Windows updates. All four verified against both machines on the first run; the Windows scan found three pending updates and changed nothing. The one coupling worth remembering was written down: the Windows shell type in the inventory must track the sshd default shell on the PC.

**2026-10-29: host hardening as code.** Two hardening passes were captured as roles, wired into one `hardening.yml` playbook with a tag per area, and the VPS joined the inventory as a third group. The method was the same for every role: first write it as an exact copy of what was already live and prove a dry run with diffs reports nothing to change on both hosts; only then change anything, through the role, and run again until it reports `changed=0`. No role is allowed to restart sshd or docker: sshd gets a config test and a reload, and a docker daemon change only prints a reminder for the next maintenance window. Two smaller playbooks came with it: a read-only audit that fails if any compose service lacks the container standard (no-new-privileges, memory and process limits, log rotation), and a Windows playbook that installs a small PowerShell syslog receiver on the gaming PC as a scheduled task with a single-address firewall rule. Traps written down: check mode can't run `validate:`, handlers or shell tasks, so sshd also gets a manual config test before an apply; two roles must never own the same file or key, so `login.defs` is split by key; a shell script containing `${#array[@]}` can't be a Jinja template because `{#` opens a comment, so scripts live in `files/`; and in check mode, tasks for a package that isn't installed yet need `ignore_errors` tied to check mode. At the end of the session the full dry run reported `changed=0` on both Linux hosts and on the gaming PC.
